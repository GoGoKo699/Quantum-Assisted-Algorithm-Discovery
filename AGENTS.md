# Repository entry instructions

## Binding hardware and research scope

Use ambitious fault-tolerant gate-model processors, **without assumed fast QRAM**.
This applies to input and dynamically created work/output tables. Ordinary logical
registers, gates, measurements, resets, classical control, and classical RAM are
allowed. Reversible formulas and compiled lookups require explicit gates, depth,
workspace, routing, precision, setup, updates, and repeated-access costs. QROM,
state-preparation, and block-encoding labels do not exempt an operation from this
accounting. No QRAM engineering program or automatic table retrofit is authorized.

Direct useful samples and reusable classical artifacts are both permitted.
Model-first exploration still comes before implementation. A dataset, hardware
demonstration, new primitive, or universal classical lower bound is not a prerequisite
to studying a credible conditional mechanism. A cheap unpriced oracle is not a
substitute for such a mechanism. No useful end-to-end quantum advantage is established;
manuscript preparation is on hold.

## Preservation and execution

Modify only `GoGoKo699/Quantum-Assisted-Algorithm-Discovery`. Preserve existing
science, negative findings, provenance, licenses, and third-party rights. Old
attached patches are not interchangeable with committed notes, even with identical
filenames. New work must not overwrite saved reports to make checks pass.

For science, run the applicable checks and report their actual scope. For maintenance,
check navigation, identity, and diffs without implying a scientific rerun or proof
audit. Root `verify.py` covers historical guided imports, not every phase. Never
run assertion-dependent verification under `-O` or `-OO`; use disposable outputs.

No external contact, paid/unattended work, manuscript revival, branch merge,
release, branch deletion, or repository administration change is authorized by
these entry instructions. Finish checkpoints before changing research candidates.
